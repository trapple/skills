## コマンド実行ルール

開発サーバー、テスト、ビルド、長時間実行されるコマンドなどは、Bashツールで直接実行せず、cmuxを使って別ペインで実行すること。

- 対象: `npm run dev`, `pnpm dev`, `yarn dev`, テスト実行全般（`vitest`, `jest`, `pytest` 等。watch/単発を問わず）, ビルド全般（`npm run build`, `tsc`, `vite build` 等）, インストール全般（`npm install`, `pnpm install`, `bundle install`, `pip install`, `brew install`, `scripts/install.sh` 等。配置・署名・依存解決を伴うものを含む）, 外部サービスアクセス（`aws`, `gcloud`, `kubectl`, `gh api`, `terraform apply` 等）, ログ tail など
- 別ペインで実行することで、メイン会話のコンテキストを汚さず、出力を継続的に確認できる
- 実行後の画面確認は `cmux-read-screen` スキルを使う
- `using-cmux` スキル（`CMUX_*` 環境変数が存在する場合に有効）の手順に従うこと

### cmux別ペインで実行するかの判断基準

次のいずれかに該当すれば cmux 別ペインで実行する:

- **常駐プロセス**: dev サーバ、ファイル監視、watch モード（プロセスが自分で終わらない）
- **長時間**: 完了まで概ね 30 秒以上かかる見込み（フルビルド、E2E スイート、重いインストール）
- **対話的**: プロンプト待ち、TUI（`vim`, `gh auth login` の対話フロー等）
- **継続観察したい**: ログ tail、ストリーミング出力
- **ビルドコマンド**: 規模・所要時間を問わず別ペイン（出力が長く会話を汚しやすく、ログを後から参照したくなるケースが多いため）
- **テスト実行**: 単発・watch を問わず別ペイン（`vitest`, `jest`, `pytest` 等。失敗ログを後から再確認したくなる、所要時間が読めない）
- **インストールコマンド**: 規模・所要時間を問わず別ペイン（`npm install`, `pnpm install`, `bundle install`, `pip install`, `brew install`, プロジェクト独自の `scripts/install.sh` 等。依存解決・ビルド・配置・署名を含むことが多く所要時間が読めない、出力が長く会話を汚しやすい）
- **外部サービスアクセス**: `aws`, `gcloud`, `az`, `kubectl`, `gh api`, `terraform`, 外部API向け `curl` など、ローカル環境外への副作用や認証情報・機微情報を伴う操作は別ペイン
  - **例外**: 副作用がなく機微情報を含まない `gh` の読み取り系サブコマンド（`gh pr view`, `gh pr list`, `gh issue view`, `gh issue list`, `gh repo view` 等）は通常Bashツールで実行してよい

いずれにも該当しない短時間単発コマンド（`ls`, `git status`, `cat`, `grep`, ローカル完結する `git` 操作など）は通常通りBashツールで実行してよい。

### 判断基準と例外が衝突したとき

「別ペイン」基準と「短時間単発」例外の両方に当てはまるように見えるコマンドは、**別ペイン基準を優先**する（テスト・ビルド・外部アクセスを短時間だからとBashに引き下げない）。

### 判断がつかないとき

判断基準のいずれにも明確に該当せず、短時間で終わるか常駐するかが事前に判別できないコマンドは、まず通常Bashで実行する。30秒以上経っても完了しない／長時間化が判明した時点で cmux 別ペインに切り替える。
