## スクリプトレビュー方針

`scripts/`・`src/scripts/`・`src/`・`bin/`・`Scripts/` 配下のスクリプト（`.ts` / `.js` / `.mjs` / `.cjs` / `.py` / `.sh` / `.cs` など）のうち、「ワンショット系」に該当するものは、以下の2タイミングで必ず `codex` スキルにレビューを依頼する。

### このルールの対象（ワンショット系の判別）

「対象」とするのは、**手動・単発で実行され、本番データや共有環境に副作用を持つプログラム**。以下のいずれかに当てはまるものを目安とする。

- `scripts/` / `src/scripts/` / `bin/` / `Scripts/` 配下のファイル（基本的にここに置かれているものは対象）
- `src/` 配下でも、CLI エントリポイント・バッチ・移行スクリプト・データ修正用ジョブ・`debug-*` 名のファイル
- 本番DBへの書き込み（INSERT/UPDATE/DELETE/DDL）、外部APIへの実行系コール、ファイル/メールの送信など、副作用が本番側に出るもの

逆に、**通常のアプリケーションコード**は本ルールの対象外。HTTPルートハンドラ・UIコンポーネント・通常リクエストフロー上のサービス層など、リクエストドリブンで動くコードは本ルールではなく通常のレビュー/テストで担保する。判断に迷う場合はユーザーに確認すること。

### 1. 修正後レビュー（コード品質チェック）

対象スクリプトを新規作成または修正した直後に実施。

- 渡す内容: 新規作成ならファイル全文、修正なら `git diff <該当ファイル>` の出力
- 観点: ロジック妥当性、エッジケース、エスケープ処理、パフォーマンス、副作用
- 指摘された懸念点があれば追加修正する

### 2. 本番実行前レビュー（実行影響チェック）

対象スクリプトを本番データに対して実行する直前に実施。

- 渡す内容: 実行コマンド、対象期間・対象環境、実行による影響範囲、想定される結果
- 観点: 実行による副作用、本番データへの影響、コスト、リカバリ可能性、想定値の妥当性
- 指摘された懸念点があれば実行を見送り再検討する

### 対象範囲（再掲）

- 本番スクリプト（`scripts/` / `src/scripts/` / `bin/` / `Scripts/` 配下の `.ts` / `.js` / `.mjs` / `.cjs` / `.py` / `.sh` / `.cs`）
- `src/` 配下でもワンショット系に該当するもの（CLI / バッチ / 移行 / データ修正）
- デバッグ用スクリプト（ファイル名が `debug-*` のもの）も対象
- 本番データへの破壊的変更（DROP TABLE、データ更新など）を伴うスクリプトは特に厳格に
