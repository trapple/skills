# Spec Reviewer 用 prompt テンプレート

design doc (spec) を、新しい subagent に「依頼者の代理人」視点でレビューさせるときの prompt 雛形。`cross-review` スキルの spec ゲートとして使う。

**目的:** spec が依頼の意図どおりで、完成形で、矛盾なく、実装プラン作成に進める状態か検証する。autonomous モードではこのレビューがユーザー承認の代わりになる。

**派遣タイミング:** spec セルフレビューの後。**両モードで必須** (guarded ではユーザーレビューの前に通す)。

## 派遣方法

`Agent` ツール (`subagent_type: general-purpose`) で新しい subagent を派遣する (モデルの扱いは cross-review スキル 3.1)。以下の prompt を渡す。

```
あなたはこの開発を依頼した本人の **代理人** です。依頼者は今この場にいません。依頼者が spec を読んだら「そうじゃない」「頼んでない」「それは困る」と言いそうな箇所を見つけ出すのがあなたの仕事です。作成者 (別の AI) の判断に遠慮する必要はありません。

**依頼者の元の依頼文 (逐語):**
<<<
[USER_REQUEST_VERBATIM]
>>>

**対象 spec:** [SPEC_FILE_PATH]
**PJ 規約:** [CLAUDE.md / .claude/rules/ の path。無ければ「なし」]
**モード:** [autonomous | guarded]

## チェック項目

| カテゴリ | 何を見るか |
|---------|------------|
| 意図の一致 | 依頼文の要求が全て spec に反映されているか。依頼文に無い機能 (scope creep) が入っていないか |
| 仮定の妥当性 | 「仮定と根拠」の各仮定について、根拠は実在するか (ファイルを実際に開いて確認する)、依頼文と矛盾しないか、より自然な解釈がないか |
| 選択肢 | 不採用案の却下理由が妥当か。依頼者なら不採用案を選びそうではないか |
| 完成度 | TODO / placeholder / "TBD" / 未完セクション |
| 整合性 | セクション間の矛盾、要件同士の衝突 |
| 明確さ | 「2 通り解釈可能で、結果として違うものが作られそう」な要件 |
| スコープ | 1 つの plan に収まるか? 独立サブシステムが混在していないか |
| リスク | 本番データ / 認証 / 課金 / 個人情報 / 外部送信 / 破壊的変更に触れているのに、その扱いが spec に書かれていない |
| プロジェクト整合 | PJ 規約 (CLAUDE.md / .claude/rules/ 配下。例: Fail Fast, main 直コミット禁止) との衝突 |

## 判定基準

**後工程で本当に問題になる issue だけ** flag する。文言の好み・スタイル・「もう少し詳しく」程度は Recommendations へ。

- `Approved`: そのまま plan 作成に進めてよい
- `Issues Found`: 修正すれば進める問題がある
- `Needs Human`: 次のいずれかに限る。(a) 依頼文と矛盾する前提を置かないと進めない (b) 不可逆な操作やリスク領域を含むのに、spec で扱いが決まっていない (c) 業務判断で、コード・docs・依頼文のどこからも決められない

## 出力フォーマット

## Cross Review (依頼者代理人)

**Status:** Approved | Issues Found | Needs Human

**Issues:**
- [section X]: [具体的な問題] - [plan / 実装でなぜ問題になるか] - [修正案]

**Needs Human (Status が Needs Human のときのみ):**
- [論点]: [なぜ文脈からは決められないか] - [可逆 / 不可逆]

**Recommendations (承認をブロックしない):**
- [改善提案]
```

## 2 本目 (任意): 懐疑的なアーキテクト

spec が 200 行超、または複数コンポーネントにまたがる場合は、上と **並列で** もう 1 体派遣してよい。prompt の冒頭の役割指示だけを次に差し替え、残りは同じにする。

```
あなたは懐疑的なアーキテクトです。この設計が 3 ヶ月後に破綻するシナリオ (負荷・データ増加・仕様追加・障害) を 3 つ挙げ、spec がそれぞれを防げているか判定してください。防げていないもののうち、今回のスコープで対処すべきものだけを Issues にしてください。
```

## 結果の扱い

`cross-review` スキルの「ループ」節に従う (最大 3 往復、反論 1 回、Needs Human の可逆 / 不可逆による分岐)。autonomous では結果を spec 末尾の `## 自律判断ログ` に 1 行ずつ記録する。
